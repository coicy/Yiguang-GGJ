# 战斗验证记录

验证日期：2026-09-06。引擎：Godot 4.7.2 stable，Windows，固定 60 Hz 物理步长。此记录覆盖战斗组件、正式八场遭遇及既有移动／能力回归；路线、检查点和通关生命周期验收由关卡集成测试另行记录。

## 已通过

| 验证 | 结果 |
|---|---|
| `tests/scene/test_combat_system.gd` | 129 项断言通过，两种战斗形态均覆盖 |
| `tests/scene/test_combat_elite_playthrough.gd` | 两形态在 720 世界单位、带实际墙体的场地内击败生产版守圃者；没有使用弹反 |
| 玩家、甲虫、孢子囊、修枝机兵、守圃者独立场景启动 | 各运行 90 帧，退出码 0，无运行时错误 |
| 正式关卡移动响应测试 | 三形态左右起步 0.100 秒，停止 0.067 秒，停止漂移 6.00 单位，反向消速 0.050 秒；吸收转换与跳跃一致性通过 |
| 原有能力与资源回归 | 扎根伸腿、转角收腿、藤蔓瞄准、上环、吸收释放锁、幼芽跳跃限制、资源与形态进度均通过 |

核心战斗断言包括：连段完整收招与输入缓存、攻击中朝向锁定、闪避／弹反取消窗口、空中动作次数限制、落地／形态变化／死亡清理、生命与受击保护、成长资源保持不变、一次挥击对每个敌人只结算一次、独立敌人生命、正面格挡／背击／重击破防、前后方向弹反、不可弹反重砸、精英霸体／二阶段／失衡，以及双方近战和高速弹体的薄墙遮挡。二阶段重砸即使在命中停顿的小时间步长下，也只发射两道冲击波。战斗期间同时禁止滑翔物理与滑翔移动状态。

既有回归脚本：`test_player_movement_response.gd`、`test_player_abilities.gd`（scene 与 unit）、`test_leg_control.gd`、`test_vine_direction.gd`、`test_vine_climb.gd`、`test_absorption_session.gd`、`test_sprout_jump_lockout.gd`、`test_resource_controller.gd`、`test_form_progression.gd`。

能力输入测试已迁移到 Q，并保留鼠标瞄准；移动测试使用正式培养室内 x=400 的开阔地面，避开新增的伸腿练习台。

## 自动精英战测量与限制

| 形态 | 模拟战斗时间 | 受到伤害 | 剩余生命 |
|---|---:|---:|---:|
| 人形 | 19.43 秒 | 0 | 5 |
| 成熟 | 19.48 秒 | 0 | 5 |

机器人读取敌人状态，精确执行绕背闪避、重击反击和跳过冲击波。它验证两种形态无需弹反也可以获胜；这些数值是熟知规则的自动操作下界，不能作为玩家首次精英战时间。当前尚未完成计划要求的三轮完整人类试玩，也未证明首次整关 10–15 分钟或首次精英战 60–120 秒，需要真实试玩记录来校准节奏。

这些 headless 检查不证明画面质量、音频混合、实际显示帧率或 Windows 导出包完整性。相关结论必须由对应实机或导出验证记录支持。

## 正式主关卡的八场遭遇回归

`tests/scene/test_greenhouse_encounters.gd` 通过 36 项断言。测试从正式 F5 入口实例化主关卡，依次进入其八场遭遇，使用玩家实际攻击／跳跃／闪避清除敌人，包含隔离庭院两轮组合。没有直接扣敌人生命，没有使用弹反，没有调整生命或伤害基线；两种形态各清八场，最终均解锁出口，全部零死亡。

| 遭遇 | 人形时间／剩余生命 | 成熟时间／剩余生命 |
|---|---|---|
| 单甲虫 | 2.32 秒／5 | 2.42 秒／5 |
| 双甲虫 | 4.03 秒／4 | 2.50 秒／5 |
| 单孢子囊 | 2.80 秒／4 | 2.52 秒／4 |
| 孢子＋甲虫 | 2.80 秒／4 | 2.52 秒／4 |
| 单机兵 | 2.32 秒／5 | 2.42 秒／5 |
| 机兵＋甲虫 | 4.03 秒／4 | 2.52 秒／5 |
| 隔离庭院两波 | 11.42 秒／1 | 9.45 秒／2 |
| 守圃者 | 23.78 秒／4 | 23.10 秒／4 |

上述时间从进入每个遭遇入口开始，包含实际命中停顿和波次间隔；每场入口的生命恢复使用正式检查点逻辑。隔离庭院在这套固定策略下分别消耗 4／3 格生命，压力高于其他遭遇，是后续新玩家试玩应优先观察的组合。

测试用入口位置 helper 隔离各场战斗，机器人能直接读取敌人状态，因此不代表连续路线通关、首次游玩时间或人类对公平性的判断。普通战斗的机器人耗时低于设计的首次体验目标；没有为了拉长时间或让机器人通过而修改敌人参数。日志：`build/greenhouse_encounters.log`。

敌人招式基线已移入 `EnemyDefinition` 的 Inspector 分组，并在四份敌人 `.tres` 中明确记录：前摇、冲锋速度／时长、攻击尺寸／伤害／击退、精英二连与二阶段阈值、硬直与破防等。迁移保持实际行为不变；孢子原来未使用的 `attack_range=400` 被写为旧 AI 实际使用的 420。迁移后组件、精英及正式八场遭遇测试全部通过，测量结果一致。

## 复现

从项目根目录，以 Godot 4.7.2 运行：

```text
godot --headless --path . --fixed-fps 60 --script res://tests/scene/test_combat_system.gd
godot --headless --path . --fixed-fps 60 --script res://tests/scene/test_combat_elite_playthrough.gd
godot --headless --path . --fixed-fps 60 --script res://tests/scene/test_player_movement_response.gd
godot --headless --path . --fixed-fps 60 --script res://tests/scene/test_greenhouse_encounters.gd
```

同时检查退出码与 stderr；不能只凭引擎退出码宣称通过。测试仅实例化生产角色／敌人及非可玩碰撞夹具，没有新增可玩的测试关卡。本页 headless 用例自身不生成截图或录像；正式主关卡截图与约 32 秒的动作姿态慢放已另行留档，见 [温室验证记录](greenhouse_validation.md)。检查产物放入有 `.gdignore` 的 `build/`，避免被导入发布资源。
