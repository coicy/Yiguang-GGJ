# 正式地形设计与制作流程

本流程根据 2026-09-06 用户补充要求独立建立。战斗验证版只证明战斗可运行，不作为正式地形交付。开发地点仍是唯一正式关卡 level_01.tscn；不另建可玩白盒、测试关卡或平行主关卡。

## 交付标准

每个区域必须能回答：这里原本用来做什么、玩家踩的是什么、平台由什么支撑、材料为什么在此发生变化、污染或植物生长如何改变了原结构。地表不能只有一张长图反复铺开，也不能把相同构件重新生成几遍后当成素材丰富度。

保留合适的模块复用，但每个新资产先分配明确职责与放置区域。不以换色、镜像、大小变化计算新增素材。已有同职责的原图先复用；只有已登记的结构/材料缺口才生成新资产。原始图、裁切定义、部件尺寸和场景实例均保留可编辑形式。

## 阶段及检查

| 阶段 | 工作 | 必须留下的证据 |
|---|---|---|
| T0 参考与资产审计 | 官方游戏截图/视频观察、现有45张源图按用途分类 | terrain_reference_study.md、terrain_asset_audit.md |
| T1 地形结构设计 | 七区材料、支撑、入口、过渡、高差、主路/回路、战斗净空 | terrain_layout_spec.md、区域设计表 |
| T2 部件规格 | 逐项列用途、锚点、自然尺寸、碰撞责任、视觉层级；去除重复职责 | 资产清单及源图联系预览 |
| T3 区域样板 | 培养室与一个战斗区先验证地表/截面/支撑的组合 | 实际镜头截图、物理边缘检查 |
| T4 完整装配 | 按七区规格装配，边缘与材质过渡单独处理 | 正式场景、可编辑部件与资源 |
| T5 关卡验收 | 两形态通路、敌人AI、遮挡、镜头、回路、局部重试 | 生产场景自动检查、逐区截图 |
| T6 体验验收 | 正常输入完整试玩、记录误判落点/死路/重复感/时间 | 真人试玩记录与改动清单 |

T0–T5 的结果可以由工具和自动测试证明相应范围；T6 不用定位脚本、无敌机器人、静态截图代替。

## 七区的材料与结构意图

| 区域 | 主要地表 | 截面与支撑 | 合理设施/自然细节 | 过渡 |
|---|---|---|---|---|
| 培养室 | 旧陶瓷/水泥地砖、局部培养土 | 实验台基座、排水沟、板底 | 墙内输养器官、育苗结构、排水格栅、管道 | 地砖开裂处长出根系和苔藓 |
| 苔藓步道 | 根系抬起的石板、完整苔藓表皮 | 土与根交织的截面、石块端头 | 草团、矮花、根部承托 | 低处出现渗水/腐木，进入孢子廊 |
| 孢子廊 | 潮湿石板与残余检修踏板 | 砌筑水渠、管线、腐蚀墙底 | 菌架、朽木、排水口 | 管线变密，接到修枝设备 |
| 修枝车间 | 金属格栅、铆接踏板、局部水泥基座 | 有间距的支架、斜撑、立柱 | 检修管、断裂设施、少量侵入根系 | 破损栈道被树根承托 |
| 树冠通路 | 枝干可行走面、天然枝叉 | 连到主干的根部承托，枝下悬垂 | 铜质藤蔓锚点、叶簇、下层回程营养点 | 主干攀上隔离庭院挡土墙 |
| 隔离庭院 | 厚石板与挡土边沿 | 砌块、加固立柱、台阶基础 | 隔离柱、低矮种植边界 | 根系与铜管汇入核心 |
| 温室核心 | 铜质检修环边缘与石质核心基座 | 核心管线、厚台基、对称承托 | 铜质根导管、少量断裂外壳 | 精英清空后通往恢复生机的出口 |

这些是用途约束，不能通过给同一地板换颜色来满足。培养室、步道、车间和树冠需要不同的可见轮廓与支撑关系。

## 视觉与物理约束

- 走面连续、边缘明确；碰撞不追随小草、苔藓毛边和无功能藤丝。
- 战斗主要读图区保持干净，草和装饰不能遮住敌人起手、脚边冲击波、玩家轮廓。
- 前景、可行走层、支撑层、背景分开；低对比大轮廓留在背景。
- 台阶、截面、板底按自然比例组装；禁止把短石板竖向拉伸成整屏墙面。
- 悬台有枝干、托架或建筑承重来源；纯单向平台仍保持清楚的薄边缘。
- 不制造装饰性尖刺与真正致死危险难以区分的情况；无伤害物件不用战斗红叉预警语言。
- 材料交界使用断口、门槛、根系跨接或设施连接；不能是两张贴图的硬拼缝。
- 小范围模块重复服务结构规律；破损、植物与设施按地点安排，不按全关固定间距撒点。
- 幼芽可进入探索支路，支路恢复资源及回主路线必须实际可达。
- 战斗房宽度、敌人同时数量和既有攻击数值由战斗规格约束，不能为了视觉改造暗中扩大难度。

## 当前状态

**用户已明确要求以《空洞骑士》实际场景为金标准，并否决当前平地拼素材的质量。** 2026-09-06 实际逐图查看官方绿径、十字路样本后，培养室/树冠/核心均未通过场景样板评审，详见 hollow_knight_scene_review.md。T1 房间轮廓与路线结构重新设计，T3 样板尚未通过；停止基于当前长直走廊的批量装配和导出。

保留已有十个独立职责的部件、二十张复用素材、可编辑资源、战斗系统及其测试。素材数量、自动可达性和稳定启动不能替代正式场景验收。新的制作顺序为：真实参考逐图拆解 → 房间连通与明暗体块 → 实际角色尺寸/镜头下的空间样板 → 依轮廓需求制作地形边缘、截面与转角 → 局部环境层次 → 试玩。先制作完整房间样板，再扩展七区。

不再固定全关地面 y=400、旧区段横坐标或横向串联；这是先前实现加入的限制，不是用户要求。保留每类战斗所需空间、两形态可达性和幼芽恢复路线等实际玩法约束。设计必须在关闭HUD、隐藏小道具时仍能看出房间用途、进出口、下一步方向与可踩边界。

2026-09-06 追加：培养室已采用完整房间近景一次生成的方式接入，植被和墙内营养源在同一母稿中设计；保留已认可的独立后景。碰撞根据新母稿重新配准，64 项实际输入检查通过，正常镜头已查看并展示；随后已修复细叶白边，并保留墙内营养源高光。树冠及核心仍未完成同等标准的正式场景，不据此开放全关批量装配。详见 nursery_asset_roles.md 与 nursery_room_review.md。

当前 Windows 包仍为之前的战斗验证版，未更新成正式地形交付。三轮真人完整试玩与首次10–15分钟体验仍待完成。旧素材及其AI衍生图的公开发布依赖不因重新组合而消失。
