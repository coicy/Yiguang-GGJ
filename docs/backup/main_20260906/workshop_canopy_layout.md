# 修枝车间与树冠通路：可施工空间布局

2026-09-06。设计交付，尚未安装或启动 Godot 验证。本轮只写本文件和两份布局 JSON；没有修改正式场景、生成器、移动或战斗代码。两份 JSON 是施工数据，不是新增的运行时地图加载器。

数据文件：[车间 layout.json](../assets/source/rooms/workshop/layout.json)、[树冠 layout.json](../assets/source/rooms/canopy/layout.json)。所有坐标为世界单位，Y 向下；路线点是角色脚底，碰撞多边形末点隐式闭合。正式画稿交付后登记统一 art_origin、art_scale，再核对边缘，不允许图片和碰撞各调各的。

## 1. 固定对接与实测参数依据

| 对接 | 脚点 |
|---|---|
| 孢子廊 → 修枝车间 | (3640,440) |
| 修枝车间 → 树冠通路 | (5080,330) |
| 树冠通路 → 隔离庭院 | (6480,170) |

依据当前 `features/forms/*.tres`：三形态水平速度均为 240；幼芽 24×24、不可跳，人形 16×34，成熟 18×46。两战斗形态跳跃初速 -400、重力 1200；理想满跳高 66.7、同高航时 0.667 秒。Movement 加速 2400，土狼 0.10 秒，缓存 0.15 秒，松开空格会截短跳跃。Vine 当前最大范围已经是 **300**，不沿用旧 260 上限；本设计另用 260 作为连接距离预算。成熟 E 上环脚点是锚点上方 14，横向绕行搜索最大 128。

必经上行均 ≤50。普通走廊至少满足成熟完整站立体积；必须满跳的起跳走廊按 46 + 66.7 的成熟身体扫掠空间检查，而不是只检查脚点。以下解析只用于设计筛选，不写成新路线通过测试。

## 2. 统一近景的施工规则

沿用已认可培养室：一幅配准近景完整绘制房体、地基、全部植被和嵌墙营养/毒脉。禁止独立小罐、毒盆或逐棵重复贴植物。运行时资源仅保留透明触发 Area 与事件反馈，亮缝位置和根墙器官在同一画稿内。

平台表是碰撞标定数据，不能被误用为逐个生成平台 PNG 的清单。车间的作业台与检修台阶属于同一厚基础；树冠用真正有厚度的枝干、冠部与悬根桥解释支撑。树冠的主枝续接只能画在受保护运动空域之外，不能为了连接根系填死藤蔓绕行通道。背景设备和根干降对比，不承担看不清的前景碰撞。

## 3. 修枝车间：下作业房 → 检修上行 → 上作业房

车间仍在 X=3640…5080 内。两间战斗房各有完整 560 宽活动平面；唯一必经升高集中在第一场结束后的 240 宽连接段。该段的窗洞让玩家回望刚清理的低位作业房，不另造无用途的反向小台或死路。

| 空间 | X 范围 / 脚面 | 用途 |
|---|---|---|
| 安全恢复入口 | 3640…3720 / 440 | 嵌墙营养只把幼芽恢复到人形；玩家在战斗触发之前完整站稳 |
| 修枝作业房 A | 3720…4280 / 440 | 1 机兵，保留 pruner_intro |
| 战后助跑段 | 4280…4336 / 440 | 右门开后才能进入 |
| 检修台肩 1 | 4336…4404 / 400 | 升 40，连续实心基础 |
| 检修台肩 2 | 4404…4472 / 360 | 升 40 |
| 检修台肩 3 | 4472…4520 / 330 | 升 30；下场入口前站稳 |
| 修枝作业房 B | 4520…5080 / 330 | 1 机兵 + 1 甲虫，保留 pruner_mixed |
| 出口 | (5080,330) | 平走接树冠，不在战斗台里插最后一阶 |

基础上缘与屋顶完整多边形、每跳起落点都已写入 JSON。工作房 A 的根壳低拱与 B 的高位修枝设备罩有不同轮廓；两幅场景的活动面都保持低噪声。可见检修设备是背景，没有在战斗中心竖一个实体柱。

当前 EncounterController 用局部 X≥52、X<540、-110<Y<20 触发，排除幼芽；两侧自动门在局部 X=0/560，敌人活动边界也随原点移动。无需增加战斗导航、敌人跳跃、额外波次或敌人参数。1280×720/2.1 显示约 609.5×342.9 世界单位，可同时看到完整 560 活动面与两边余量。

入口与检修检查点分别在 (3680,420)、(4504,310)，其节点沿用比脚面高20的旧表现规则。开始战斗后，控制器仍用其现有局部重试点更新快照。不要把检查点场景原点、角色脚面和摄影中心混为一个点。

车间没有毒雾、枯萎点或坠落洞。幼芽即使从上一段退化而来，也可在进入第一间前恢复；人形和成熟都通过同一三阶。未通过第一场不能绕过右门跳上检修段。

## 4. 树冠上路：沿枝折返，再越过冠部

入口脚面330，主路先向右升到240，再折向左升到150，重新向右跨到树冠60，最后向右下落到215的根桥肩部，再跳到170出口。最高点比最终出口高110，用于绕过树冠体量；它不是为了延长步行而增加的平台列。

| 台面 | X 范围 / Y | 行进关系 |
|---|---|---|
| 入口 | 5080…5260 / 330 | 嵌墙成长点(5160,315)，可选择成熟 |
| B1 | 5340…5460 / 285 | 右上45 |
| B2 | 5480…5580 / 240 | 右上45 |
| B3 | 5340…5440 / 195 | 向左上45，第一次折返 |
| B4 | 5200…5320 / 150 | 再向左上45，回望入口 |
| B5 | 5360…5500 / 100 | 转向右，上50 |
| B6 | 5560…5720 / 60 | 右上40，冠部 |
| B7 | 5740…5860 / 110 | 安全向右下50 |
| B8 根桥肩部 | 5880…5980 / 215 | 可预见的安全下行105；与下路共用 |
| 出口枝桥 | 6020…6480 / 170 | 上45后平走离开 |

主路不要求冲刺、弹反、藤蔓或持续滑翔。满跳落点均在实际台面内；JSON 指定起跳区，避免在低顶之下误把直上跳当成必经动作。尤其 B3 必须结束在 X=5440，让 B1 的右侧起跳区开放；B5 底面保持114，使 B2 向左上跳时成熟头顶仍有约13.3余量。B3 向左起跳在5350附近，先离开 B5 下方再上行。B4→B5 是唯一50高的上行，不再增加同高的大缺口。

B7 与 ReturnRootBridge 在5840…5860有实体重叠，构成连续下降肩部与悬根桥体。桥体上方的返回阶梯与下方的幼芽通道从同一块完整轮廓里产生，不能拆成六条悬浮台。

## 5. 下路：接住、枯萎、幼芽通道、恢复、返回

主枝下方接住地面为 Y=475。西侧入口基础另有426、378两级回入口台肩；已保留的战斗形态也可原路重新尝试主枝。向东的低路是明确的形态恢复回路：

1. 落到安全下腔，沿脚面475走到嵌墙毒脉(5810,460)。
2. 人形按 E 一阶段、成熟两阶段变成幼芽；这里是主动毒液交互，没有持续毒雾。
3. 幼芽水平走过 X=5900…6380、顶443/底475的32高根桥下通道。
4. 完全出洞后到嵌墙营养(6440,460)，按阶段恢复人形或成熟。
5. 从东向西沿根桥的430、385、340、305、260、215六个真实台肩上行，升幅45/45/45/35/45/45。
6. 到达共用 B8，再跳到出口枝桥170，回到主路。

这条低路可主动选择，也负责失误后的恢复；没有在通道尽头放一个无功能观景点。幼芽本身不必跳跃或攀环才到营养源；营养触发48×48，最早接触约 X=6402，已在6380出口之后22以上，不会在洞内突然长大。东侧封口在6460…6480、Y≥178，只关闭下腔，不堵上方170出门脚面。

根桥下通道最长480，按当前幼芽240速度约2秒纯步行；制作时间不用于机械拉长关卡。根桥下地面水平无小凸起，近景植物不侵占32净高。入口与出口的触发器不允许跨到桥上，隔着实体根桥不能吸收另一层资源。

返回时最需保留的头顶余量：出口枝桥底178；从305台肩满跳的成熟头顶约192.3，余量14.3。260台肩的下一跳先走到X6000，已在出口桥左端6020以西，再向左上跳215。桥底加厚或把起跳点移到桥下都会造成顶头，不能留到机器人调参时用减速/短跳掩盖。

## 6. 成熟三环捷径与镜头

| 环 | 世界锚点 | 实际起点 → 落点 | 距离 |
|---|---|---|---|
| Ring0 | (5520,130) | B1右缘(5450,285) → B2(5520,240) | 170.1 |
| Ring1 | (5400,15) | B2(5520,240) → B5(5400,100) | 255 |
| Ring2 | (5610,-30) | B5(5400,100) → B6(5610,60) | 247.0 |

环1跳过两块左侧枝台，构成成熟形态的真实效率收益；人形依靠上述共同跳跃链完整通过。环2命名按现有 Ring0/1/2 顺序保留，施工时不能只换画图而留旧锚点世界坐标。

Ring1 的直接上行可能碰到 B5 底部，须由既有 E 多段绕行穿过 B5东端5500与B6西端5560之间的60宽空隙。允许的成熟身体通道为 X5509…5551，建议绕行脚点X5512…5524；相对锚点最大124，处于当前128搜索范围内。该通道从下部B2延伸到B5上方，禁止画成实体主干。这里必须单独跑真实Q/E和ShapeCast检查，文档不把解析间距当作已接通。

镜头区域在 JSON 中给出二维矩形、中心、缩放和优先级。主要区别：

- 车间：入口/检修用房间视域，战斗仍由 Encounter 高优先级固定镜头接管。
- 树冠：入口、中层、上方折返、最高冠部、东侧下降及下部左右恢复腔分别构图。上方折返中心(5500,85)，最高冠部中心(5500,15)，均zoom2.0；以脚点Y115分区，避免B3脚面195被底部HUD遮住，同时保证最高上环时头顶-90仍在画面。
- 东侧在X6410后交回FRAMED，直到隔离庭院接管。JSON里的 framed_follow 表示不放固定RoomRegion覆盖，不是要求给当前脚本写不存在的字段。
- 固定区域必须测试正向、反向及坠落，不只检查静态中心。敌人与角色脚面不能被紧凑HUD遮住；下落目标应在起跳/落下前可见。

当前 RoomRegion 的 camera_center 是相对区域节点的坐标。JSON为审阅方便存世界中心；施工时转换为 center - region.position。两形态共同相机缩放不能按贴图大小随意改。

## 7. 施工后的最小验收

| 验证 | 必须成立 |
|---|---|
| 两场车间战斗 | 原两波完整，560宽活动面内无升降；人形/成熟不靠弹反清场；被击退、敌人掉出边界、死亡重试和右门均正确 |
| 车间连接 | 清场后按实际左右/空格通过40/40/30三阶；未清场不能绕门；三阶前后角色不穿模型 |
| 树冠上路 | 人形、成熟各从(5080,330)到(6480,170)，不传送、不用闪避/藤蔓补跳跃距离；每个上行≤50 |
| 下路恢复 | 各从实际掉落开始，成熟和人形分别主动枯萎→幼芽穿完整通道→洞外恢复原形态→六阶→共用出口；不直接写资源/形态 |
| 幼芽安全 | 入口保持幼芽跳过首营养时，也能从左侧台肩向下走到低路并抵达东端营养；通道内无必须跳过的凸起 |
| 三环 | 实际鼠标瞄准Q、E连续运动；环1绕行不撞B5/B6；目标点与头顶避开屋顶；松开后落在实际枝面 |
| 镜头 | 战斗接管优先；上路折返、从上路跌落、三环上行、下路恢复、跨层死亡重试无旧镜头残留或出画 |
| 视觉 | 完整近景中地基、根桥和枝干厚度成立；资源是嵌墙器官；无独立罐盆/重复植被贴片；碰撞上沿与画稿误差目标≤3世界单位 |
