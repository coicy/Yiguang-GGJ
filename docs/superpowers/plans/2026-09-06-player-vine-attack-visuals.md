# 主角攻击藤蔓素材与动画重制计划

日期：2026-09-06
状态：素材、组件、十套攻击动画及自动／图形验证已实施。真人盲认验收尚未执行，实际交付与证据见 ../../vine_attack_validation.md。

目标：玩家在正式关卡、正常镜头和正常攻击速度下，能直接认出主角挥出的是有叶片、茎节与弹性的植物藤蔓；能看懂它从手部伸出、弯曲甩动、命中和收回的过程。

## 1. 当前问题与依据

用户反馈：目前完全看不出攻击物是藤蔓，只像绿色棒子。

代码与既有截图支持这个判断：

- features/combat/combat_visual.gd 的 _draw_whip() 用三层等宽 draw_polyline 画藤身，普通攻击宽度为 2.5、重击为 3.2 世界单位，没有沿藤身分布的叶片和粗细递减。
- _curve() 只有一个控制点，生成单段二次曲线，不能表现明显的 S 形弯曲和沿藤身传递的甩动。
- 藤蔓到前摇的 60% 才出现，有效段结束后最多 0.08 秒内回收并透明消失；缺少可辨认的卷曲起势和有形体的回卷。
- 明亮中心线、多层浅色残影、尖箭头状末端强化了光束和硬杆印象。
- PlayerVisuals._combat_hand_point() 已提供 hand_L_3 手腕骨骼加掌长偏移的挂接位置，可作为接入基础；角色战斗动作由 humanoid_poses.tres、mature_poses.tres 叠加到既有 Spine 骨骼。
- build/qa/combat-visuals/main_humanoid_attack.webp 与 combat_poses_heavy.webp 为本次查看的既有证据，并非本次重新运行的验收结果。

结论：需要同时重做藤蔓实体的素材、柔性动作和角色发力配合，单纯加粗或增加发光不能解决识别问题。

## 2. 视觉方案

沿用现有角色的深色轮廓、黄绿色植物体、清晰叶片和卡通块面。藤蔓从手部叶鞘延伸，保留主角轮廓与既有造型。

必须具备四个识别特征：

1. 根部粗、末端细，茎上有少量节结，藤梢有明显卷须。
2. 叶片长在藤身上，叶柄位置固定，随局部藤段转动；形态变化不能看成叶片粒子贴在光线上。
3. 起势呈 C 形或 S 形，发力依次经过根部、中段、藤梢，末端最后甩出并回弹。
4. 实体轮廓与叶片承担识别，挥击残影只短暂强调速度。关闭发光和残影后仍应看得出是藤蔓。

人形使用较细藤身与 2–3 处清晰叶簇，动作紧凑；成熟形态使用较厚基部与 3–4 处叶簇，弯曲幅度和末端滞后更明显。具体数量以正式镜头下不糊成一团为准。两者共享植物语言，分别配置外形和动画。

## 3. 独立素材交付

制作一套共享藤身部件，加两种形态的基部与藤梢变体。以现有角色全身参考和正式战斗截图为风格、比例依据。

| 素材 | 制作要求 | 用途 |
| --- | --- | --- |
| 藤身贴图 | 深色边缘、浅色块面、少量纵向纹理，能沿弯曲网格连续变形 | 主体，避免绳节拼接和等宽光条 |
| 手部连接叶鞘 | 两形态各一款，遮住藤根与原手部交接处 | 看起来从身体长出，避免悬空 |
| 茎节 | 少量明暗变化，与主体配色一致 | 提供植物茎的结构 |
| 叶片／叶簇 | 2–3 种轮廓，叶柄为固定挂点 | 构成可辨认的植物剪影 |
| 卷曲藤梢 | 人形与成熟各一款，细而弯，避免箭头或枪尖 | 强化柔软、活体感 |
| 短促挥击残影 | 与实际扫击方向一致，透明度低于主体 | 只在高速有效段辅助读招 |

运行时采用透明 PNG 部件和图集，初始以一张 1024×1024 图集容纳为目标，按实际使用尺寸校准；导出后检查透明边缘、缩小采样和图集边界渗色。叶片与茎分开导出，叶片尺寸不能随着攻击距离被整体拉长。尺寸最终以 1280×720、普通战斗与精英镜头下的可读性决定。

源文件放 assets/source/combat/vine_attack/，运行时放 assets/runtime/combat/vine_attack/。保留制作原图、分部件源、图集区域／挂点说明、实际使用的导出设置；若使用图像生成，保留提示词和角色参考来源。可编辑动画交付为 Godot 场景与动画资源，不冒称新增 Spine 原工程或不存在的 PSD 分层文件。

## 4. 动画与组件方案

采用独立的 VineWhipVisual 场景：Godot 原生 Skeleton2D／Bone2D 驱动带贴图的 Polygon2D，叶片与藤梢挂到相应藤段；AnimationPlayer 保存可编辑关键帧。先以约 8–10 段骨骼制作样板，按弯曲质量调整，不引入自由绳索物理。

这是本项目的方案选择。Godot 官方文档确认 Polygon2D 支持纹理、UV 和 Skeleton2D 骨骼变形：[Polygon2D 文档](https://docs.godotengine.org/en/stable/classes/class_polygon2d.html)。本项目 Godot 4.7.2 与 Spine 包装层的实际配合在样板阶段验证。

组件分工：

- CombatController 继续拥有招式、时间、朝向、攻击距离和伤害结算。
- PlayerVisuals 提供当前形态、攻击姿势和手部挂接变换，并把战斗状态传给藤蔓组件。
- VineWhipVisual 只拥有材质、骨骼、叶片、残影与动画表现，不结算伤害，不反向控制人物移动。
- 同一个组件读取两形态的视觉配置和五招动画；不复制玩家场景。

时序与空间约定：

- 运行时从 CombatController.elapsed 和招式阶段计算动画采样位置；动画不使用独立自由运行的计时器，命中停顿、暂停和成熟形态时序倍率必须同步。
- 完整读取手部位置和方向，并处理形态缩放、偏移与左右翻转。骨骼挂点必须在 Spine 本帧姿势更新后采样，避免手与藤根相差一帧。
- 拆分根部、藤身和叶片的缩放：攻击距离只改变藤身有效展开长度，不能把整张藤蔓和叶片横向拉伸。
- 连段、闪避取消、受击、死亡、切形态和重试时立即清理旧动作与残影。连续挥击使用明确的姿势交接，防止突然复位成直线。
- 需要经过身体后方的蓄势段使用明确的前后绘制层；不依赖修改既有 Spine 图集或任意穿过脸部掩盖遮挡问题。
- 新组件接入后移除 CombatVisual 中旧藤鞭主体及旧残影绘制，保留该脚本现有的弹反／闪避表现。

## 5. 招式制作表

每招都制作“卷曲准备 → 根部带动 → 藤梢甩出 → 回弹收回”，关键姿势直接按当前前摇／有效／收招时间对齐。以下是动作方向，不新增攻击能力。

| 招式 | 藤蔓动作 | 人物配合 |
| --- | --- | --- |
| light_1 | 手边短 C 形展开，向前快速抽出，末端最后绷紧 | 肩部先转，前臂随后甩出，收手清晰 |
| light_2 | 顺上一击回弹反向回抽，出现可见反向弯曲 | 转腰带手，避免再次播放同一挥棒姿势 |
| light_3 | 较大的 S 形蓄势，完整挥出后明显回卷 | 全身发力，第三击轮廓和前两击有差异 |
| heavy | 粗基部藤蔓在肩上弯曲蓄势，向前下方抽砸 | 抬臂与躯干蓄势更明显，命中后跟随前压 |
| air | 藤梢从身侧向斜下方抽出，再向手边回收 | 保留空中收腿姿势，不能表现成落地砸击 |

覆盖两形态各五招，共十套动作配置，分别检查左右朝向。闪避、弹反、受击仅处理藤蔓的中断与交接，本轮不扩成整套防御动作重制。

## 7. 最终验收标准

- 正式普通战斗镜头约 2.1、精英镜头约 1.65，在 1280×720 正常播放时，可以看见附着于藤身的叶片和粗细变化。
- 对不了解改动的人播放三段短片，不提示“藤蔓”，记录其对攻击物的描述；若仍被描述为棍棒或光束，视觉识别目标未达成。
- 去掉发光与残影后，实体仍有茎、叶、卷须及柔性甩动特征。
- 藤根不离手，左右翻转无跳变，弯曲无可见断节／拉花；每招能看清蓄势、甩出与收回。
- 人形紧凑、成熟舒展；十套动作均有录像证据，慢放只辅助排错，不能代替正常速度验收。
- 有效攻击范围和命中时刻具有可信的视觉解释；中断后没有悬空藤蔓、残影或残留判定。
